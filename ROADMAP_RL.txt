# RL Curriculum Roadmap

End goal: a single policy (or family of policies sharing a backbone) that
can assemble a complete vanilla Factorio rocket from raw resources.

Progression is roughly the vanilla tech-tree order. Each row is a
training stage. Stages share the same arena infrastructure — only the
recipe / input_items / target_output change via `arena_set_task` (mod
0.9.x). New entity types unlock as we hit recipes that need them.

**Input policy (per JJ):** for MOST stages the agent gets crafted plates
(iron-plate, copper-plate, etc.) directly in the input chest. The
smelting-focused stages (Phase E) are the ones where the agent gets raw
ores and has to smelt them first. The "compose from raw" capstone is
Phase H (stage 100).

**Factorio 2.0 note:** filter-inserter no longer exists in vanilla 2.0
(2.0.76 in this project). Any stage that would have used it is replaced
with the regular inserter or a different entity.

Column legend:
  STAGE   = ordinal in the curriculum
  PRODUCT = what the arena's assembler/furnace must deliver to the output chest
  INPUTS  = ingredients placed in input chest(s) by arena_reset
  NOTES   = arena requirements / new entity unlocks / tweaks

## Notes for me

- Stages 1-25 reuse the existing 8x8 arena. Stage 26+ likely needs a bigger arena (16x16) for the chains involved.
- Each stage's `arena_set_task` spec lives in `bridge/rl/curriculum_specs.py` (TO BE WRITTEN).
- BC trains a stage from one or more hand-built demos (`demonstration_<stage>.py`). PPO fine-tunes if the BC checkpoint doesn't already crush the target.
- Knowledge transfer: each new stage starts from the previous best checkpoint, then BC-augments with the new demo.
- For stages needing new entity TYPES (burner furnace, chemical plant, pumpjack, etc.), the env's MultiDiscrete action space needs new entity slots — that's a mod + bridge change at the appropriate stage gate.
