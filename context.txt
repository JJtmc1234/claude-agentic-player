# Claude Agentic Player — Stable Context

Slow-changing reference. Read at the start of every new conversation. Update

## Project goal

Claude controls a Factorio character via RCON + a custom mod, eventually
playing as a co-op teammate. Current focus: RL training of factory layouts
in a fixed 8x8 walled "arena" (see PLAN_RL.txt, PLAN_CURRICULUM.txt).

## Mod conventions

- Latest version: 0.9.7 (always bump info.json + the pong string in control.lua together).
- Storage namespace: `__claude-companion__` (separate from `__level__` — `/silent-command` runs in scenario context and CANNOT see the mod's storage; route through remote functions or arena_debug_state).
- Remote interfaces: `claude` (chat, walking, mining, ping) + `claude_rl` (arena_*).
- Arena state persists across save/load in `storage.arena`. After `restart.ps1` the arena bounds, chests, loaders all survive in the save; storage updates from same session don't persist past a non-saving stop. To switch task: `claude_rl.arena_set_task({recipe_name=..., output_item=..., target_output=N, input_items=[...], sim_max_ticks=T})` (added in 0.9.0).
- `arena_setup` accepts a player_name OR no argument (uses `game.surfaces.nauvis`) since 0.9.2 — works headlessly.
- Multi-input support since 0.9.1: arena_setup classifies chests/loaders by x (west of bounds = input, east = output). With multiple input chests/loaders, arena_reset distributes `input_items[i]` to chest[i].
- Loaders get `.active=false` during build phase (so chest shows true refill amount) and `.active=true` on `arena_start_simulate` (since 0.8.20).
- Directions: raw integers 0/2/4/6/8/10/12/14. `defines.direction.north_east` is nil in 2.0 — DO NOT USE.
- Inserter geometry: `direction=EAST` means picks east, drops west. So `dir=W` (3 in env mapping) picks west, drops east.

## RL pipeline

- Arena: **16x16** walled grid. Bounds `{x_min=-20, y_min=70, x_max=-5, y_max=85}`. 1 wall ring perimeter (not 4).
- Loaders: 2 input at (-21, 77.5) + (-21, 78.5), 1 output at (-4, 77.5).
- Entities: 0=transport-belt, 1=inserter, 2=assembling-machine-1, 3=no-op.
- Action space: MultiDiscrete([4, 256, 4]). Tile index = row * 16 + col.
- Obs: 10 channels (was 12 — chest channels dropped in 0.9.4) × 16 × 16 + 3 globals = 2563 dims.
- Hard placement caps per type (env.py): belt=30, inserter=12, asm=6 (relaxed for parallel chains).
- Diminishing returns within useful range: `max(0.3, 1 / (1 + 0.5 * n_already))`.
- Base step rewards: belt=+3, inserter=+4, assembler=+10.
- Episode budget: `MAX_BUILD_ACTIONS = 60`, `MIN_ACTIONS_BEFORE_NOOP = 12`.
- Sim phase: `SIM_MAX_TICKS_OVERRIDE = 3600` (60 game-sec at game.speed=64; agent rate-limit is the yellow inserter 0.83s cycle).
- Episode reward components (mod 0.9.7 arena_score):
  - per_gear: chest×50 + asm_output×20 + inserter×15 + belt×10 (PARTIAL CREDIT for in-transit items)
  - reached_bonus: +1000 when out_count >= target
  - base: -200 if 0 chest output, else 0
  - speed_bonus: (sim_max_ticks - ticks_taken) * 0.1, fires only on reached
  - chain_alive gate: zeros chain_points, activity, functional_inserter, etc if no chain active
  - chain_points: graph walk (loader→belt→inserter→asm→inserter→belt→loader) plus neighborhood pts (belt pairs ×3, good drops ×10, good pickups ×10)
  - penalties: useless_belt ×5, invalid_action ×1

## Agentic-play library (`bridge/agent/`)

Distillation of day-1+2 agentic play (2026-06-20) into a clean module library:
- `agent.Agent.connect()` → context-manager that resolves char unum from `storage.claude_char_unum`
- `agent.movement` — walking with chunked long-distance + step_aside
- `agent.placement` — snap-aware placement (geometry encoded), blocker clearing, take_back
- `agent.mining` — mine_at with walk-in retry, mine_nearest, chop_trees
- `agent.fuel` — single-slot-aware fueling (won't error on mixed-fuel slot)
- `agent.inventory` — chest transfers, craft+wait helpers
- `agent.geometry` — snap math + drill_drop_position (+1.3 not +2 in 2.0!) + inserter helpers
- `agent.layouts` — declarative LineSpecs for iron line, drill→chest, power chain

All modules <150 lines. Library written offline; smoke-test against live server before relying.
See `bridge/agent/README.md` and `POWER_CHAIN.md`.

## Factorio 2.0 geometry constants we keep getting wrong

- **Burner-mining-drill drop**: center + (0.5, 1.296875) for south-facing — NOT +2.
  Drop tile is FIRST row south of drill's south edge.
- **Inserter direction**: side it PICKS FROM, not where it drops. dir=0 (north)
  → pickup north, drop south. The mod's chain_walk reward depends on this.
- **2x2 / 1x1 snap mismatch**: 2x2 entities snap to integer centers (x, y),
  1x1 to half-integer (x.5, y.5). Inserter Y south of 2x2 furnace at (fx, fy)
  must be `fy + 1` (snaps to `fy + 1.5`) for pickup to land ON the furnace's
  south row. `fy + 2` is one tile too south.
- **Offshore-pump direction is auto-detected** by terrain in 2.0; the `direction`
  arg is ignored. Query `pump.fluidbox.get_pipe_connections(1)[1].target_position`
  to learn where to put the receiving pipe.
- **Boiler 3x2 dir=4** (east-flow): water inputs on N+S of west column, steam out east.

## Training recipe (current best practice)

1. Design partial demo: ~7 actions covering input chain + asm + output start (but
   stopping short of completing the output chain to the loader).
2. BC pretrain: 50 reps × 2000 epochs to loss < 1 so the demo is faithfully
   reproduced (loss > 2 → policy defaults to "belt at any tile" because belts
   are the majority entity in demos).
3. PPO from BC ckpt: ent_coef 0.08-0.15, lr 5e-5 to 1e-4, target_kl 0.005-0.01.
   Without target_kl, PPO drifts away from BC in ~20 episodes.
4. Mod 0.9.7's partial-credit shaping pays the agent for in-transit items so
   even pre-loader chains get reward.

## Editor convention for arena setup

JJ places these entities in the editor; `arena_setup` reads their positions:
- 2 "valve" entities (any prototype with type='valve', e.g. top-up-valve) marking opposite corners of the 8x8 grid.
- 2 loaders just OUTSIDE the grid (one west = input, one east = output).
- 2 containers next to the loaders (left of input loader = input chest, right of output loader = output chest).
