TEAM CONTEXT — Manager + Employees
==================================

Hierarchy:

    Human (JJ)
        ↕  (bidirectional, 1:1)
    Manager (single agent)
        ↕  (1:many — Manager talks to each Employee individually)
    Employee-1  Employee-2  Employee-3  Employee-4  (...expandable)

The Human ONLY talks to Manager under normal operation. Employees DO
NOT communicate with the Human. Manager is the sole escalation point
for human-input decisions.

The Human retains a break-glass ability to interrupt any Employee's
work directly (Ctrl+C, in-session interrupt, force-stop). This is
NOT normal; it's an override.

Character system: currently only ONE character exists in-game
(storage.claude_char_unum). Multi-character mod support is DESIGNED

Branches: Manager operates on `main` only. Each Employee has ONE
working branch: `employee-1`, `employee-2`, `employee-3`,
`employee-4`. Never push directly to `main` as an Employee. See
`git-workflow.md`.

CORE RULES (all agents)
--------------------------------------------------------------------------

- Update your own section on every substantive action.
- Employees NEVER address the Human directly. All Human-facing
  updates go through Manager.
- Manager NEVER edits code as an implementer — Manager assigns
  Employees to do implementation. Exception: docs (context.txt,
  bug-log.md, merge-log.md) and merge commits.
- Placement conflicts: never assign two Employees to place entities
  in the same tile-region in the same batch. See tile-lock design
  in `thoughts.txt`.
- Movement, mining, fuel checks safe to parallelize; place_entity
  and take_from_chest can race on shared state.
- Workshop chest at (-30.5, 41.5) is the shared supply-drop.
- Buffer chest from JJ at (-6.5, -32.5) — check periodically for
  intermediate-products JJ may drop.
