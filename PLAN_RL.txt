Claude Agentic Player — RL plan + status (live document)
=========================================================

Last updated: 2026-05-30 afternoon (JJ AFK, agent running autonomously).

Note on jargon (defined here, used freely below):
  - RL: Reinforcement Learning. Agent learns from trial-and-error reward.
  - Agent: the trained policy (here, a small MLP that decides
    "what to place where" each step).
  - Environment: a gymnasium-compatible interface wrapping the mod.
  - Episode: one full attempt — build, simulate, measure, reset.
  - PPO: Proximal Policy Optimization (the algorithm we use).
  - MaskablePPO: PPO variant that knows which actions are valid each step.
  - BC: Behavioral Cloning — supervised pre-training on demos.
  - Stable-Baselines3 (SB3): library that implements PPO/MaskablePPO.

------------------------------------------------------------
1. The task
------------------------------------------------------------
Inside a walled 8x8 arena on the Factorio map:
  - West edge: input chest + input loader (refilled with iron-plate each
    episode)
  - East edge: output chest + output loader
  - 8x8 interior: agent places transport-belts, inserters, and one or
    more assembling-machine-1s (with gear-wheel recipe auto-set)

Episode lifecycle: arena_reset wipes interior + refills input + clears
loader. Agent gets up to 25 actions to build. Then arena_start_simulate
runs the world at game.speed=64 until output chest has 50 gears or
1800 sim ticks elapse. Reward computed from outcome.

------------------------------------------------------------
2. Observation
------------------------------------------------------------
Shape: (8, 8, 12) tensor + 3 globals = 771 floats.

Channels per tile (one-hot):
  0: empty
  1-4: belt facing N / E / S / W
  5-8: inserter facing N / E / S / W
  9: assembling-machine-1 anchor
  10: input chest
  11: output chest

Globals: tick-in-episode, output-count/50, input-count/100.

------------------------------------------------------------
3. Action space
------------------------------------------------------------
MultiDiscrete([4, 64, 4])  —  entity, tile, direction.
  entity: 0=belt, 1=inserter, 2=assembler, 3=no-op
  tile:   0..63 (row-major in the 8x8 grid)
  direction: 0=N, 1=E, 2=S, 3=W

Constraints enforced in env:
  - First 10 actions: no-op is converted to invalid (-1) and continues
    the episode. Forces the agent to actually build instead of bailing.
  - Step rewards: +3 for valid placement, -0.2 for invalid attempts.

------------------------------------------------------------
4. Reward function (mod-side, computed at episode end)
------------------------------------------------------------
Base:
  reached 50 gears: +100 + (sim_max_ticks - ticks_taken)*0.1 + 100 reach_bonus
  partial output: -100 + 80*(out/50)  (so 25 gears = -60)
  empty output: -100  (was -1000, lowered to escape local min)

Shaping:
  +10 per functional inserter (pickup AND drop on real entities)
  -5  per useless belt (no neighbor either side)
  -1  per invalid action attempt
  +chain_pts (graph-walk: each piece of input-loader -> belts -> inserter
                -> gear-assembler -> inserter -> belts -> output-loader
                worth 5-50, including direct-to-loader bypasses)

------------------------------------------------------------
5. Implementations
------------------------------------------------------------
Mod: claude-companion 0.8.6 (published on portal).

Bridge:
  bridge/rl/env.py            — vanilla gym env (used by PPO)
  bridge/rl/masked_env.py     — variant with action_masks() for MaskablePPO
  bridge/rl/bc.py             — behavioral cloning on JJ's hand demo
  bridge/rl/train.py          — PPO training (--checkpoint for warm start)
  bridge/rl/train_masked.py   — MaskablePPO training
  bridge/rl/compare.py        — eval N episodes of a checkpoint
  bridge/rl/replay_demo.py    — verify demo can be reproduced via env.step
  bridge/rl/eval_bc.py        — single-episode rollout with a checkpoint
  bridge/rl/dump_weights.py   — dump a checkpoint to .txt for inspection
  bridge/random_episode.py    — random baseline (with bigger-first bias)

Server: server/restart.ps1 — save -> stop -> deploy -> publish -> start.

------------------------------------------------------------
6. What was tried and the result
------------------------------------------------------------
v0 random episodes: confirmed pipeline works end-to-end.

BC on 14-example hand demo: cross-entropy loss decreased from 8.32 to
4.41 over 50 epochs, but the resulting policy was too biased toward one
tile under deterministic play, and "complete goobiness" under sampling.
14 examples is too few for a 3075-dim input.

PPO from scratch on 16x16 arena: stuck at "no-op = safest" local minimum
because every action led to -1000 (no-output severe penalty), so the
agent rolled no-op early to minimize negative.

Fix attempts that worked:
  - lowered no-output base from -1000 to -100
  - suppressed early no-ops (first 10 actions must be real placements)
  - amplified step shaping: +3 valid / -0.2 invalid (was +1 / -0.5)
  - ent_coef=0.1 to keep policy distribution wide
  - rebuilt arena from 16x16 to 8x8 (action space 1536 -> 64, much smaller)

Net result for v8 first rollout: ep_rew_mean -1010 -> -90, ep_len_mean
4.86 -> 15.4. The policy is now exploring meaningfully.

Pending experiments:
  - MaskablePPO with tile-empty action masks (likely much faster)
  - Resume from a partial PPO checkpoint with longer training budget
  - If gears succeed: build a circuit arena (copper-cable + iron-plate ->
    electronic-circuit) and repeat the training loop

------------------------------------------------------------
7. Known limitations
------------------------------------------------------------
- Editor "Extra Settings -> Tags" does not persist on placed entities in
  Factorio 2.0 (we tested). We use position-based identification instead.
- game.get_entity_by_unit_number only returns entities explicitly
  registered with script.register_on_entity_destroyed in 2.0; chests
  placed in-editor aren't, so we look them up by position too.
- auto_pause in server-settings.json clamps sim speed even with our mod
  setting game.tick_paused=false. We disabled auto_pause (server-wide).
- Mod storage is reset on server load if no save was made after a fresh
  arena_setup. Always save after setup so the next restart finds it.

------------------------------------------------------------
8. How to use this stuff
------------------------------------------------------------
Start a fresh PPO training:
    python bridge/rl/train.py --steps 5000 --save checkpoints/my_run.zip

Continue training from a checkpoint:
    python bridge/rl/train.py --checkpoint checkpoints/my_run.zip --steps 3000

Train with action masking (recommended):
    python bridge/rl/train_masked.py --steps 5000 --save checkpoints/masked.zip

Evaluate a checkpoint:
    python bridge/rl/compare.py --checkpoint checkpoints/my_run.zip --episodes 5

Replay JJ's hand-built demo to test the env:
    python bridge/rl/replay_demo.py

Restart server (saves + deploys + publishes + starts + pings):
    server\restart.ps1
