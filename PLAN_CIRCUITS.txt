Claude Agentic Player — Circuit Task Plan (DRAFT, not yet deployed)
====================================================================

Drafted while gear training runs. Goal: extend the RL pipeline from
"produce iron-gear-wheel" to "produce electronic-circuit," transferring
knowledge from the gear-trained MaskablePPO checkpoint.

------------------------------------------------------------
1. Why circuits next
------------------------------------------------------------
Same arena, same action space, slightly harder recipe. Lets us validate
that the agent can ADAPT — taking what it learned (place assembler in
the middle, inserters on each side, belts to/from loaders) and
applying it to a new product. If transfer learning works here, we have
a real path to scaling the agent up to more complex factories.

------------------------------------------------------------
2. Recipe differences
------------------------------------------------------------
iron-gear-wheel:    2 iron-plate         -> 1 gear,    0.5s
electronic-circuit: 1 iron-plate + 3 copper-cable -> 1 circuit, 0.5s

Two-ingredient recipe is the wrinkle. In Factorio, an assembler with
mixed-ingredient recipe needs BOTH items in its input slot. The
inserter doesn't filter — it grabs whatever is on the belt — but if
both items are on the same belt, the assembler can hold both ingredients
fine. The ratio doesn't have to be exact; the assembler just consumes
when it has enough.

Simplest setup: input chest contains BOTH iron-plate AND copper-cable.
The same chain (belt -> inserter -> assembler -> inserter -> belt)
works. The agent learned chain placement; it just needs a different
recipe set on the assembler.

------------------------------------------------------------
3. Required changes
------------------------------------------------------------
Mod (claude-companion 0.9.0 — NOT YET DEPLOYED):
  - storage.arena.recipe_name = 'iron-gear-wheel' | 'electronic-circuit'
    (today it's hardcoded; promote to runtime config)
  - storage.arena.input_items = list of {name, count} to refill on reset
    (today: one item; new: list, e.g. [{iron-plate, 100}, {copper-cable, 100}])
  - arena_set_task(opts) remote function: updates recipe + input_items +
    target_output + output_item in storage.arena
  - arena_reset uses input_items list to refill
  - arena_place sets the configured recipe on newly placed assemblers
    (currently hardcoded to 'iron-gear-wheel')
  - arena_score's gears_total / per_gear_reward generalized to whatever
    output_item is currently configured

Bridge (no mod changes needed to ship these — just config):
  - bridge/rl/demonstration_circuits.py — same layout as 8x8 gear demo;
    different name to reflect different task
  - bridge/rl/train_circuits.py — warm-start from a gear MaskablePPO
    checkpoint, call arena_set_task('electronic-circuit') once at start

------------------------------------------------------------
4. Knowledge transfer
------------------------------------------------------------
The MaskablePPO policy network has these layers:
  policy_net.0  (input,  3075 -> 128)
  policy_net.2  (hidden, 128  -> 128)
  action_net    (output, 128  -> n_actions logits)

Loading a gear-trained checkpoint into a circuit-task env:
  - obs_space is the SAME (same arena shape) -> weights compatible
  - action_space is the SAME (same MultiDiscrete) -> weights compatible
  - The agent's input observations LOOK identical to gear training. It
    won't even know the task changed — until it gets reward signal from
    a different ingredient mix. Then PPO updates push the policy.

So transfer is "for free" — just load and continue training. The policy
should converge faster than a fresh one because spatial reasoning is
preserved (place assembler, inserters around it, belts connecting).

------------------------------------------------------------
5. Realistic risks
------------------------------------------------------------
- Ratio imbalance: if the belt carries 100 plates first and 0 cables,
  the assembler stalls. Could happen if the inserter happens to grab
  plates first. Solution: shuffle input items via game.surfaces[...]
  .find_entities_filtered + sort, or insert plates/cables alternating.
- Bigger search space: circuit needs MORE items per craft (4 items vs
  2 for gears), so each craft takes longer and the output count grows
  slower. Should LOWER target_output (maybe 10 not 50) so episodes
  finish in reasonable time.
- The agent's value head was trained on gear-reward magnitudes. With a
  different output_item, the per_gear_reward scaling may shift the
  reward magnitudes. PPO has built-in adaptation but might need a few
  rollouts to recalibrate.

------------------------------------------------------------
6. Execution order (when deploying)
------------------------------------------------------------
1. Stop current training.
2. Save current MaskablePPO gear checkpoint as `gear_baseline.zip`.
3. Apply mod 0.9.0 changes to control.lua (see TODOs in
   mod/claude-companion/circuit_changes.lua — separate draft file).
4. Run server/restart.ps1.
5. Call arena_set_task('electronic-circuit', {iron-plate=100, copper-cable=100}, target_output=10).
6. Verify with replay of circuit demo (bridge/rl/replay_demo_circuits.py — TODO).
7. Launch train_circuits.py from gear_baseline.zip.
